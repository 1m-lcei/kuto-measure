# Svelte移行の検証記録

2026-09-30。移行前は `478b681`、作業ブランチは `svelte-migration`。既存の未追跡画像添付は変更・コミットせず保持しました。pushは実行していません。

全UIをSvelte 5へ移し、TypeScriptと既存Viteを継続使用しています。手動のパネル同期、SVGの `innerHTML` 全置換、一覧の再構築、再描画後のSVGフォーカス復元を削除しました。キー付き描画でノードとフォーカスを保持します。フォーム・ダイアログ・popover・ファイル保存はブラウザ標準APIを使用します。

測定、投影、画像読み込み、Undo/Redo、JSON version 1、保存基準version 1は既存ロジックを再利用します。画面とPNGは `annotations.ts` で同じ座標とラベル配置を計算します。画像・編集データを送信する処理は追加していません。

検証コマンドは `bun run typecheck`、`bun run lint`、`bun run test`、`bun run build`、ビルド後の `bun run test:browser` です。単体テスト31件、Chromium・Firefox・WebKitのブラウザテストを実行しました。既存の保存・PNG・相対距離・グループ・基準・領域・Undo/Redo・タッチ検証に加え、パン中の無更新、SVG/一覧ノードとフォーカスの保持、テーマ再読込、領域状態の文言、入力文字列のエスケープを検証します。

性能計測はWindows、headless Chromium 153.0.8010.12、1440×1000、device scale 1、1536×709の生成画像、24ピン・8距離線で実施しました。同一の本番ビルド用テストで90フレーム×8イベントを3回実行し、以下は各回の値の中央値です。ドラッグは実際にピンの座標が変わることも検査します。生データは [performance/svelte-migration.json](performance/svelte-migration.json) にあります。

SVG内に追加された要素数は90フレームで約22,700個から0個になりました。操作中のパネル更新は移行前後とも0です。パンは表示位置だけを更新し、投影・ラベル配置を再計算しません。ポインターイベントはフレームごとにまとめ、確定時は最後の座標を反映します。

途中の測定でズーム中央値の増加があったため、CPUプロファイルからラベル配置の衝突判定を確認しました。残りのペナルティが非負であることを利用して、既存の最良候補に勝てない候補の採点を途中で終了します。探索候補・評価式・選択結果は変えていません。固定シードの60ケースで旧実装と配置結果が完全一致しました。距離表記の `Intl.NumberFormat` も2桁・4桁の2個を再利用します。

同じ32注釈の画面を移行前後で撮影したところ、幅1440px・390pxともPNGがバイト単位で一致しました。CSSは変更していません。デスクトップのSHA-256は `b8d9b04d1491359c1829375e4ea5b7cd34373287644e6c672363324e615aeaf6`、モバイルは `0c83952df8c43f77d32fdf027b24c5a9f6c1f4a06aaba1238bb46dd9d3f781cb` です。

合計gzipは21,045 B（59.4%）増加しました。HTML内のUIがJavaScriptへ移り、Svelteランタイムとコンパイル後のテンプレートが加わったためです。旧DOM処理・不要な対話用SVG文字列生成の削除、状態別要素の集約、繰り返しフォームの共通描画で初期移行版から縮小しましたが、元のVanilla構成より大きいという制約は残ります。アイコン等の変更していない静的アセットはこの集計から除外しています。

再計測:

```powershell
bun run build
$env:PERF_LABEL = 'after'
bun run test:performance
# 比較する旧ビルドを指定する場合
$env:PERF_DIST = '旧ビルドのdistディレクトリ'
$env:PERF_LABEL = 'before'
bun run test:performance
Remove-Item Env:PERF_DIST
Remove-Item Env:PERF_LABEL
```

出力先は `test-results/performance-<ラベル>.json` です。ビルド・ブラウザテストと性能計測を同時に走らせないでください。フレーム間隔は合成イベントを使ったheadless環境の測定値で、実機の入力遅延やINPではありません。実機モバイル・低速端末での性能、手動スクリーンリーダー操作は未検証です。大量の注釈では従来の上限付きラベル探索の計算量が制約になります。
