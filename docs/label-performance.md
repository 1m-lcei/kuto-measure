# ラベル配置の検証記録

2026-10-17。比較元は `26bd8fe`。現在の仕様は[開発文書](development.md#保存と表示)を参照。

## 対象と判断

ラベル候補を採点するときの、描画線とラベル矩形・引出線の交差判定にSIMDを適用した。矩形同士の重なり、配置済みラベルとの比較、候補の生成・採用順はJavaScriptに残す。

JavaScript側も軸名による動的な参照をなくし、描画線の方向と `Math.hypot` による長さを配置ごとに計算する。SIMD版は同じ前計算の値を倍精度配列に格納し、2線分ずつ評価する。準備済み配列を候補間で再利用し、早期打ち切りは2本ごとに行う。罰点は非負なので採用結果は変わらない。

`wabt` の既存ビルド環境を使い、実行時依存は追加していない。Wasmは約0.95KB。画像や編集データは外部送信しない。

## 計測方法

Windows x64、Ryzen 7 9700X、Chromium 153.0.8010.12。

- 生成画像1536×709に対応する24ピン・8距離線・4円、240ピン・80距離線・13円を使う。ラベル数36／333、描画線分数150／510。
- 同一ブラウザ内で、保存した旧配置関数、JavaScript改善版、SIMD版を比較する。各方式3回以上かつ250ms以上のウォームアップ後、順序を巡回して5試行。各試行80ms以上の平均時間を1配置あたりに換算する。
- 文字計測、配置ごとの前計算、Wasm用配列へのコピーと呼び出しを含む。Wasmの取得・初期化、画像読み込み、DOM/Svelte描画は含まない。
- 計測前に全方式の配置結果が完全一致することを確認する。CPUクロックや他プロセスの負荷は固定しない。

## 結果

中央値、括弧内は5試行の最小〜最大。単位はms/配置。

| 条件 | 旧実装 | JavaScript改善版 | SIMD版 |
| --- | --- | --- | --- |
| 24ピン・36ラベル | 7.50 (7.11–7.69) | 3.90 (3.82–3.96) | 3.01 (2.93–3.07) |
| 240ピン・333ラベル | 840.8 (821.1–867.7) | 382.3 (373.0–446.3) | 339.2 (320.6–359.1) |

旧実装からの短縮はどちらも約60%。JavaScript改善版に対するSIMDの追加短縮は約23%・11%。改善のすべてをSIMDの効果とは扱わない。生データは [performance/labels.json](performance/labels.json)。

## 回帰と再現

```sh
bun run typecheck
bun run lint
bun run test
bun run build
bun run test:browser
bun tests/label-performance.ts
```

`tests/labels-reference.ts` に旧配置関数を固定し、単体テストでJavaScript・SIMD双方の配置を比較する。平行・長さゼロ・境界接触・極端な座標・奇数本・メモリ拡張・早期打ち切り・倍率・密集・長い文字・測定コールバックからの再入を扱う。メモリ拡張失敗時のフォールバックも確認する。

ブラウザ検証では本番ビルドのWasm初期化と、破損・取得失敗時の同一配置を比較する。既存のラベル操作・ズーム・ホバー・PNG出力検証も実行する。

型検査（警告0）、lint、単体51件、ビルド、Chromium・Firefox・WebKitの全ブラウザ検証が成功した。性能値に固定の合否閾値は設けていない。

計測はデスクトップChromiumのみで、実機スマートフォンは未測定。貪欲配置の探索量自体は減らしていないため、多数の注釈では再配置に待ち時間が残る。関数の短縮率をそのまま画面全体の高速化率とは扱わない。
