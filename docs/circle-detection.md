# 地面上の円の自動検出

「画像・基準」の「画像から円を検出」で、現在のゲーム領域とカメラ設定を使って複数の円を探します。
画像上には番号付きの候補を表示します。輪郭との重なりを確認し、候補ごとに「基準円にする」または「補助円に追加」を選びます。
選び終えたら、全幅の強調ボタン「候補を閉じる」で候補表示を消し、測定・編集を続けます。採用済みの円は残ります。検出0件の場合は「円を検出できませんでした」と枠付きで表示します。
基準円にした場合はゲーム内半径を入力します。既存の基準円を置き換えると、以前のゲーム内半径は引き継ぎません。
補助円への追加には、基準円のゲーム内半径または相対距離の基準線によるスケールが必要です。
採用した円は通常の編集・Undo/Redo・JSON保存・PNG出力の対象です。

検出だけでは編集履歴を変更しません。候補は保存・PNG出力に含まれず、画像・カメラ設定・ゲーム領域を変更すると破棄します。
処理中は中止できます。画像と編集データはブラウザ内で処理し、外部に送信しません。

## 判定と限界

RGBの輪郭点を既存の逆投影で地面座標に戻し、円を当てはめます。
輪郭の連結成分内の3点から円の候補を作り、外れ値を除いて再推定します。512点を超える大きな連結成分には、2点と一方の法線方向を使う探索を追加し、複数の円やエフェクトがつながった輪郭からも候補を作ります。追加の候補も同じ条件で検証します。輪郭の向きと円周方向の分布で候補を絞り、線の内外の重複をまとめます。
候補の周囲に細い明線がある場合は、円周上の96方向で近傍の輝度ピークを探し、中心と半径を合わせ直します。
探索範囲は縮小画像上で輪郭の法線方向に±6pxです。発光の幅広い部分や局所的な光を避け、十分な点が同じ円に沿う場合だけ補正します。
明線が不明瞭な場合は元の推定を維持し、一律に半径を広げる補正は行いません。
補正した円が輪郭検証を通らない場合は、補正前の円を同じ条件で再検証します。
補正後の円周を720方向で再検証します。縮小画像の法線方向±1.5pxに、円周の法線と約20°以内で一致するRGB勾配（強度14以上）がある方向を数え、全方向の65%以上に支持がある候補を残します。
画面外の方向は支持に数えません。既存の勾配を再利用し、まばらな床模様などが円周48区間を埋めるだけの候補を除外します。
カメラ設定そのものは推定しません。画像上の楕円の中心を地面の円の中心とみなす処理も行いません。

処理量を抑えるため、ゲーム領域を縦横比を保って長辺1,000px以下に縮小します。
最大160輪郭、1輪郭512点・96試行×3回、検証16,000点、表示20候補に制限します。
512点を超える輪郭への追加探索は、同じ512点を使い384試行×3回を上限とします。
円周48区間のうち65%以上に輪郭の支持があることを求めます。これは正解確率ではありません。
部分的な隠れや複数円の重なりに対応しますが、小さい円、細い・淡い線、大きな欠け、密な模様、近接する同心円などでは見落としや誤検出があり得ます。
カメラ設定が異なる画像では正しく当てはまりません。候補がない場合は領域とカメラ設定を確認し、手動で円を合わせてください。
仰角などを目視で比較する場合は、先に検出した候補を基準円として採用し、その円を表示したままカメラ設定を変えます。
自動検出は現在のカメラ設定を前提とするため、検出の成否だけでカメラ設定の正誤は判断できません。

## 実行と検証

画像処理と当てはめは専用Web Workerで実行します。繰り返しの一致点数計算にはWebAssemblyの `f64x2` SIMDを使い、2点ずつ判定します。
SIMDの検証・読み込み・初期化に失敗した場合は、同じ判定式のJavaScript実装を使います。
Wasmは同梱の約0.22KBのモジュールで、外部CDNや実行時ライブラリは利用しません。
`src/circle-score.wat` から `bun run build:wasm` で生成し、dev・test・buildの各コマンドから自動実行します。コンパイラ `wabt` は開発依存だけです。

単体テストは複数円、重なり、一部の欠け、まばらな断片の除外、同心円、発光の外側の細い明線、暗い・淡い輪郭、透視投影・ロール・ゲーム領域のオフセット、無地・直線・透明画像、SIMDとの一致を確認します。
ブラウザテストは候補表示と採用、Undo/Redo、JSON保存、SIMDフォールバック、中止、設定・画像変更による破棄を確認します。
実際のゲーム画像での検出精度は別途確認が必要です。
